# Conversation Reader 0.9.9 quality review

19 November 2026 · Local working copy · Motorola Edge 60 Neo on Android 16 and Android 15 simulations

I would make the next patch about **getting into a conversation reliably**. Two issues reproduced on the Motorola deserve first attention. Word counting can stall the library, and a model name that varies only in capitalization can close the app. Exact-position resume worked in the phone test.

## What worked

- **Continue reading restored the exact line on the Motorola.** I expanded a prompt with a 450-paragraph reply, scrolled eight times, returned to the library, stopped the test app, and resumed from a fresh process. Paragraph 35, character offset 97, returned to the same vertical position of 1,333 pixels. This covers leaving through Back with the same font, orientation, and window size.
- **The optimized release passed its phone smoke test.** It opened a synthetic conversation, displayed Markdown, exercised repeated Next and Previous jumps, expanded and collapsed Thinking, changed all three fonts, and entered and exited search.
- **One ordinary reading session scrolled smoothly.** Android recorded 1,170 frames across eight scripted swipes in the numbered reply. One frame was marked janky, the median was 5 ms and the 95th percentile was 13 ms. This sample covers plain paragraphs on one phone. Tables, very long unbroken lines, and different display refresh rates deserve separate runs. A repeatable performance suite could use Android's startup and frame timing metrics. [Android Macrobenchmark metrics](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-metrics)
- **The existing host suite passed all 79 tests.** It includes a 1,000-message synthetic conversation, search focus, folder-cache invalidation, imported file handling, bookmarks, Markdown, reading position, and activity recreation. The regular release APK built at 2,506,132 bytes. Release lint found zero errors and 40 warnings, including 32 Kotlin API style suggestions.
- **Three of four checked-in device tests passed on the first run.** The fourth expected the selected model's exact label without its external-link arrow. With only that expectation updated in a temporary test copy, all four passed on the phone. Update the checked-in selector to identify the model action by its accessible name.

## Fixes in recommended order

| Priority | Reproduction and impact | Suggested fix and acceptance check |
| --- | --- | --- |
| First | **Word counting blocks the library on the phone.** With 200 manually imported JSON files, 44,703 bytes each and 8.94 MB total, the optimized app failed to expose a file card within 180 seconds. Five samples of its main thread, taken between 3 and 105 seconds after launch, all traced back to the app's word count and Android's regex matcher. | Count words in one pass off the UI thread and persist the count with import metadata. Reuse it for cards, Models, and sorting. Repeat the 200-file test and verify that a cached file opens while any background indexing continues. |
| High | **Models can crash.** Give two versions of one reply the model names `LocalModel` and `localmodel`. Open Models and tap that group. Both the optimized Motorola build and the simulation threw the same duplicate-key exception. Android recorded an app crash. | Normalize model names for grouping and deduplicate conversation IDs within each group. Preserve the display spelling. The group should show a count of one and open one working card. |
| High | **Short windows can make the library unusable.** At 720 × 320 dp in landscape, four imports and a Continue reading card left the Imported list a 0 × 0 visible viewport. The fully expanded sort sheet also clipped Done and had no scrollable content. | Put the library heading, Continue reading, and sort controls in the scrolling list on short screens. Let sort choices scroll while keeping Done accessible. Verify a user can open the fourth file and change sort in landscape and split screen. |
| High | **Deleting an import leaves dead cards.** Open an import, star it, then choose Remove from library. It remains visible in Recent and Bookmarked. Tapping it reports that the conversation is unavailable. | Remove the imported copy's references, bookmark, and reading state together. If it was the last-read file, Continue reading should offer the next available one. Exercise deletion from the actual menu and restart before checking the lists. |
| Medium | **Library search misses partial text.** A reply containing “blueberry harvest” matched the complete words. Typing “blue” or “blueberry har” returned no body match. Some filtered views also suggested restarting or updating the index when a query simply had no matches. | Apply prefix matching to the final word as the user types. Preserve Folders' name/path scope. Show a clear-search action on an empty filter. A useful follow-up is a tappable matched snippet in All files that opens the passage directly while a regular title tap still opens collapsed prompts. |
| Medium | **Reader navigation sometimes points to the wrong text.** A search phrase split across two rendering blocks counted as one hit but neither half was highlighted. Contents jumped to an earlier mention of a heading, 4,495 characters above the real heading. Next also reset a previously chosen prompt version to the file default. | Intersect whole-reply match ranges with each visible block, derive Contents positions from rendered heading spans, and use the selected prompt version for Next and Previous. Test a phrase crossing a block boundary, repeated heading names, and a prompt with two versions. |
| Medium | **Bookmarked sorts by a different date from the one it shows.** With Date descending, a recently opened conversation dated 2020 appeared above a conversation dated 2025. | Use the date displayed on the card for Bookmarked. Use an explicit Last opened sort in Recent. Test with creation and last-opened dates in opposite orders. |

## Where performance work will pay off

- **Time until the library exposed a file card on the Motorola** was a median 2.48 seconds with one import across five indexed launches. With twelve imports it took 22.19–22.31 seconds across three launches, including the initial indexing run. With 200 imports the probe timed out at three minutes. Each JSON was 44,703 bytes and the method includes Android instrumentation overhead. A separate ordinary launch with 200 imports drew its first activity frame in 235 ms. Measure until a reader can open a file as well as until the first frame appears. These tests exercised manually imported copies. The linked-folder scan has its own metadata cache.
- **The proposed word counter was tested independently on the same phone.** On a 43,648-character reply, both implementations counted exactly 6,300 words. The existing Kotlin implementation took a median **839 ms**. A single Java regex matcher advancing through the reply took **3.9 ms** using the same pattern. Each median covers five timed calls after a warm-up in the isolated debug test app. This comparison measures counting one reply. Re-measure full library startup after integrating the change. [Current word counter](../app/src/main/java/cz/jan/conversationreader/TextLength.kt)
- Opening an imported item through Continue reading, Recent, Bookmarked, or Models calls a loader that reparses every imported JSON. Store lightweight card metadata and resolve a single imported conversation by ID. Compute word counts when a file enters or changes in the library, then reuse the result for cards and sorting. [Library store](../app/src/main/java/cz/jan/conversationreader/LibraryStore.kt) · [Library cards and sorting](../app/src/main/java/cz/jan/conversationreader/MainActivity.kt)
- Search a 64-message conversation twice with different terms. Each query rendered Markdown for all 64 messages again in the host probe. Reuse the reader's rendered text and cache searchable text for alternate versions. A separate probe exposed repeated scans from the start of long, unbroken paragraphs. Doubling one paragraph from one million to two million characters increased splitting time from 106 to 448 ms on the host. Limit separator searches to the current block. [Reader search](../app/src/main/java/cz/jan/conversationreader/ConversationReader.kt) · [Text splitting and rendering](../app/src/main/java/cz/jan/conversationreader/ReadingDocument.kt)
- An unchanged linked-folder refresh checks for each file separately in the full-text table. Android SQLite's query plan showed a table scan per key. Load indexed IDs once per refresh or use a keyed lookup. A folder-switch test also found that the previous folder's body text remained in the local search index after its card disappeared. Reconcile rows only after a successful scan and preserve separate manual imports. [Folder scan](../app/src/main/java/cz/jan/conversationreader/LibraryStore.kt) · [Search index](../app/src/main/java/cz/jan/conversationreader/LibrarySearchIndex.kt)

## Smaller improvements

- On first launch, put **Link a folder** beside **Import files**. Linking the PC-synced directory is a primary workflow, and the current empty Imported screen only offers the single-file route directly.
- Give both font-size sliders accessible names and announce their units. Their simulated accessibility nodes exposed only numeric ranges. Label **Aa** as **Reading preferences** and the version arrows as **Previous version** and **Next version**.
- At 320 dp wide with Android text set to 115% and the app interface at 130%, the Imported tab was truncated. Allow the tab strip to scroll or adapt to the measured label widths.
- In light mode, the small Continue reading caption measured 3.93:1 against its card. Darken the caption to reach 4.5:1. When Android uses Light and the app uses Dark, the window still requests dark system-bar icons. Set icon appearance from the chosen app theme. [Android accessibility guidance](https://developer.android.com/guide/topics/ui/accessibility/apps)

## Scope

Tests used synthetic conversations and a separate phone application ID. I removed the temporary phone packages after testing and verified the regular reader was still installed. The layout and accessibility measurements came from an API 35 simulation. The actual spoken TalkBack experience, external file-manager handoffs, and revoked permissions on a physical document provider remain unverified. This review did not change the app or its version.
